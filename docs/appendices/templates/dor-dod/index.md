# DoR / DoD テンプレ

## Definition of Ready（入口条件）

- [ ] 背景/目的が書かれている
- [ ] スコープ/非スコープが書かれている
- [ ] 受け入れ条件がある
- [ ] 受け入れ条件ごとの確認方法がある
- [ ] 根拠と未確定点が分離されている
- [ ] 依存関係/リスクが整理されている

## Definition of Done（常時必須の出口条件）

- [ ] 完了判断と、受け入れ条件またはクローズ理由の対応を記録した
- [ ] 確認方法を実施し、結果と証跡を記録した
- [ ] 残課題、リスク、再確認条件を記録した
- [ ] follow-up が必要な場合は Issue、Owner、期限または再確認条件を記録した

## Definition of Done（条件付きゲート）

各ゲートの状態を `PASS / FAIL / PENDING / N/A` で記録する。適用するゲートが成功すれば PASS、失敗中なら FAIL、確認未完了なら PENDING、条件非該当の場合だけ N/A とする。N/A の場合は理由・判断根拠・Owner を空欄にしない。

|ゲート|適用条件|状態（PASS/FAIL/PENDING/N/A）|証跡、失敗/未完了内容、または N/A 理由・根拠・Owner|
|---|---|---|---|
|PR 説明|PR を作成した|||
|レビュー対応・未解決 thread 0|レビューを伴う PR がある|||
|CI green|対象変更を検証する CI が構成されている|||
|merge 後の main checks|main 向け checks が構成されている。merge 前は PENDING、merge 後に PASS/FAIL を判定する|||
|デプロイ/公開反映|デプロイ先または公開物がある|||
|ロールバック|切り戻し可能な利用者/運用影響がある|||
|ナレッジ化|運用や再利用手順へ影響する|||

## 運用メモ

- DoR を満たせない場合は、着手しない理由ではなく「不足情報をいつ誰が埋めるか」として管理する
- DoD を満たせない項目は、未完了のまま閉じず、follow-up Issue として分離する
- レビュー対応は、修正だけでなく「対応しない判断」も返信して証跡に残す
- 適用する条件付きゲートがすべて PASS で、FAIL / PENDING が 0 の場合だけ完了にする
- N/A は条件非該当だけに使う。構成済み CI の失敗、main checks の失敗、公開対象の未反映は N/A にしない
