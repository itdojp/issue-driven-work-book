## 記入例（悪い例→良い例）

### 悪い例

- UI を良くする

### 良い例

- 背景: 操作ミスが多く問い合わせが増加
- 目的: 主要導線の誤操作率を下げる
- スコープ: 入力フォームのバリデーション/文言
- 非スコープ: 画面全体のデザイン刷新
- 受け入れ条件: Given=必須項目が未入力、When=保存、Then=保存されずどの項目が不足か分かる（誤操作率が 5%→1% 以下、例）
- 確認方法: E2E、手動 UI 確認、2週間移動平均のメトリクス
- 根拠・未確定点: 問い合わせログと操作ログを根拠にする。文言ポリシーは別 Issue で確認
